# Решения

Короткий журнал: что решили и почему. Новые записи сверху.

## 2026-10-16 — обзор выгодности и персонажи (этап 1d + 2)

**Обзор:** категории — фильтры по SDE:
- корабли: категория 6 + раса (Калдари = 1) + meta group (T1 = нет/1, T2 = 2, T3 = 14);
- субсистемы: категория 32;
- риги: группы категории 7 с названием «Rig …»;
- реакции: продукты reaction-формул;
- «Мои чертежи»: продукты чертежей, которые есть у персонажей.

Для каждого предмета считается полное дерево через тот же `calculate`. Партия = столько ранов, чтобы джоба продукта шла `targetJobDays` (по умолчанию 5), но не больше ранов BPC (инвент или свой) и `maxProductionLimit`. ISK/ч = прибыль / время джобы продукта (занятость слота). Объёмы продаж берутся из `/markets/{region}/history`: среднее в день за 30 и 7 дней (дни без сделок считаются как 0) плюс «партия = N дней рынка».

**Персонажи:** EVE SSO, auth code flow (web app, client secret в `.env.local`). JWT проверяется по JWKS, issuer и audience. Refresh-токен шифруется AES-256-GCM, ключ в `data/secret.key`. Синхронизация:
- скиллы: активный уровень;
- чертежи персонажа и корпорации: корп. только с ролью Director, иначе пометка, а не ошибка;
- джобы.

**Как персонажи влияют на расчёт:**
- **Скиллы:** реальные уровни (лучший среди всех или выбранный персонаж). Industry / Advanced Industry / Reactions и каждый скилл из требований чертежа идут по своему уровню. Инвент: скилл с «Encryption» в названии /40, два научных /30.
- **Чертежи:** лучший экземпляр (BPO > BPC, потом ME, потом TE). Если чертёж продукта есть, по умолчанию «свой», с его ME/TE и без стоимости BPC. Если нет, берётся инвент (когда возможен). Промежуточные чертежи тоже берут ME/TE из своих.
- Без персонажей всё как раньше, из настроек.

## 2026-10-16 — порог выгоды для промежуточных

**Компонент строим, только если это выгодно по ISK/ч** (`minBuildIskPerHour`, по умолчанию 100 000). Выгода = (цена покупки − себестоимость постройки) за единицу / часы СОБСТВЕННОЙ джобы этого узла на единицу. Порог не действует на корень и на ручные решения. В дереве причина «выгода ниже порога», а в подсказке видна выгода в ISK/ч.

## 2026-10-16 — риги по группам, скидка системы

**Риги — список правил**, а не один тир на работу. У каждого рига: работа (производство / реакции / инвент / копирование), группы предметов (корабли, компоненты, структуры, модули/дроны/патроны, топливо, всё) и БАЗОВЫЕ ME% и TE% из Show Info рига. Множитель зоны (×1.9 лоусек, ×2.1 нули) применяется сверху. Группы сопоставлены с категориями SDE: корабли = 6, компоненты = 17 (advanced, capital, T3, R.A.M.), структуры = 22/23/65/66, модули и прочее = 7/8/18/32/87, топливо = группа 1136. Если два рига покрывают одно и то же, берётся лучший. Старый формат пресетов конвертируется автоматически (`normalizeRigs`, миграция 0002).

**Скидка системы на джобы** (`systemJobBonus`, например бонус ФВ в Auner) пока уменьшает только часть от cost index, налоги и SCC не трогает. Точное правило CCP не подтверждено: сверить по подсказке стоимости джобы в окне Industry и поправить, если игра режет и налог.

**Джобы** показывают разбивку стоимости (EIV, индекс, налог, SCC) для построчной сверки с игрой.

## 2026-10-16 — этап 1c

**Дерево сборки в три прохода** (`src/engine/tree.ts`):
1. Обход рецептов от корня с защитой от циклов.
2. Снизу вверх считается себестоимость единицы. На каждом узле решение «строить», если это дешевле рынка, или ручной оверрайд. Расход здесь без округления, для решения этого достаточно.
3. Сверху вниз в топологическом порядке суммируется спрос по всему дереву. Раны = ceil(спрос / выход за ран), с настоящим округлением ME. Общие полуфабрикаты (например, Fulleroferrocene для четырёх компонентов) становятся ОДНОЙ джобой, излишек показывается.

**Рецепт предмета:** сначала manufacturing, иначе reaction. Fuel blocks тоже считаются строимыми, если это дешевле. Отключаются ручным «купить».

**Инвент:** шанс = база × (1 + Encryption/40 + (наука1 + наука2)/30). Стоимость попытки = датакоры + реликт (для T3) + джоба (2% EIV продукта × индекс). Стоимость на ран = попытка / шанс / раны BPC. По умолчанию берётся источник с минимальной стоимостью на ран. Скопированный T1 BPC считается бесплатным (свой BPO), декрипторы пока не поддерживаются.

**ME/TE:** у корня из инвента ME 2 / TE 4, у своего чертежа — что введено. У всех промежуточных чертежей настройка «ME/TE чертежей компонентов» (10/20). На этапе 2 возьмём реальные значения из чертежей персонажей.

**Цены в UI:** сначала кэш ESI (`price_cache`), если пусто — фикстуры, и UI показывает источник и возраст. «Обновить цены» тянет adjusted prices, cost indices всех систем и ордера Jita для всех рыночных типов дерева.

**«В час джоб»** = прибыль / СУММАРНОЕ время всех джоб. Параллельность слотов не учитывается.

**Системы** импортируются из `mapSolarSystems.jsonl`, если файл есть. Если нет, поиск систем недоступен, но импорт не падает.

## 2026-10-16 — этап 1a

**Официальный SDE (JSONL), а не Fuzzwork.** В 2025 CCP переделали SDE и выпускают его в формате JSON Lines вместе с каждым деплоем Tranquility. Скрипт `sde:download` сам собирает нормализованный `data/sde.sqlite` (таблицы `sde_*`). Мы не зависим от чужой схемы дампа. Парсер терпим к переименованиям полей (`typeID`/`typeId`, `name` строкой или `{en}`), а `sanityCheck` роняет импорт, если что-то распарсилось подозрительно мало. Старый `data/sde.sqlite` при этом не затирается.

**Две БД.** `data/sde.sqlite` (заменяется целиком на каждый патч) и `data/app.sqlite` (настройки, пресеты, кэш цен, планы; Drizzle-миграции в `drizzle/`). Обе в `.gitignore`.

**Движок чистый.** `src/engine` не делает IO. Это проверяется ESLint-правилом: импорт `fs`/`node:*`/`@/db`/`@/esi`/`@/sde` и `fetch` внутри engine дают ошибку. Поэтому весь расчёт тестируется в облаке.

**Все игровые константы в `src/engine/bonuses.ts`** с пометкой `// verify`. Это бонусы структур, ригов, множители безопасности, SCC, налоги. Пометка снимается после сверки с игрой или EVE Guru.

**Формула материалов:** `max(runs, ceil(round(base × runs × (1 − ME/100) × mult, 2)))`. Округление до 2 знаков перед `ceil` такое же, как в игре (51.0048 → 51). Для реакций ME не применяется, ролевой бонус материалов у Engineering Complex только на manufacturing.

**Выход джобы = runs × products[].quantity.** Это закрывает баг таблицы с R.A.M. (192 шт = 2 рана). `portionSize` из types — это про переработку, для производства не используется.

**EIV считается от базовых количеств** (без ME) × adjusted price. Стоимость джобы: `EIV × factor × (index × (1 − бонус структуры) + facility tax + SCC)`. Для инвента и копирования factor = 0.02 (сверить).

**Режимы цен и комиссии:**
| | sell | buy | split |
|---|---|---|---|
| цена | min sell | max buy | середина |
| материалы: комиссия | нет (берём с рынка) | broker fee (ставим buy-ордер) | broker fee |
| продукт: комиссия | tax + broker | только tax (продаём в buy) | tax + broker |

**Цены только по станции Jita 4-4** (location_id 60003760), а не минимум по региону The Forge, как в старой таблице. Ограничение: buy-ордера с радиусом region/system, выставленные на других станциях, пока не учитываются.

**Риги:** пока одна пара (material/time) на активность в пресете. В игре риги действуют на группы предметов (корабли, модули, компоненты…). Разбивка по группам будет позже, когда появятся реальные пресеты.

**Пресеты по умолчанию:** Sotiyo (null, по умолчанию), Tatara (реакции), NPC Station Jita. Риги пустые, Ник заполнит сам.
